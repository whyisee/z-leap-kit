# 弹珠打撤 PVP 模式设计方案

本文档用于定义《弹珠打撤》的 PVP 玩法、界面、匹配、房间、压力系统、养成竞技、服务端边界和分阶段落地方案。

PVP 的目标不是把当前单人战斗直接改成“双方弹珠互撞”，而是在保留弹珠清场、局内构筑、局外养成和搜打撤张力的基础上，做成更适合网络同步和移动端观看的对战体验。

## 1. 设计结论

PVP 推荐分两条线落地：

| 阶段 | 模式 | 核心体验 | 技术目标 |
| --- | --- | --- | --- |
| 第 1 阶段 | 1v1 服务器压制赛 | 双方自动战斗，比清场效率、抗压能力和构筑强度 | 跑通服务器对手快照、匹配、房间、事件同步、胜负结算 |
| 第 2 阶段 | 养成竞技 1v1 | 保留局外养成，按战力匹配和修正 | 接入战力分层、段位、奖励 |
| 第 3 阶段 | 多人压制赛 | 1vN 或小组混战，点击头像切换观察目标 | 验证多人头像和右侧战场切换 |
| 第 4 阶段 | 大逃杀搜打撤 | 多人同局淘汰，搜资源、施压、撤离、保战利品 | 形成真正的 PVP 搜打撤模式 |

第一版 PVP 的最小可玩目标：

- 1v1。
- 自动战斗。
- 不需要玩家手动选择战术升级。
- 升级时系统自动从 3 个选项中选择。
- 左侧显示自己的战场，占横向空间约 2/3。
- 右侧显示当前选中的对手战场，占横向空间约 1/3。
- 顶部显示对战玩家头像，后续支持多人头像。
- 点击头像切换右侧显示的对手。
- 双方通过击杀效率积累压力，并把压力转化为对对手的干扰。
- 第一版入口先进入 1v1 快速匹配，10 秒内优先寻找真实玩家。
- 10 秒内没有真实玩家时，才接入服务器 AI 对手快照，前端只渲染后端返回的对手战场。
- 真实玩家和服务器 AI 复用同一套对手快照和事件结构，服务端负责房间、匹配、事件、结算和校验。

## 2. PVP 设计原则

### 2.1 自动战斗优先

PVP 中不做手动战术选择，原因：

- 减少操作负担，让玩家专注观察对手、阵容和压力节奏。
- 避免双方升级暂停时间不同，影响对战节奏。
- 降低移动端误触和小屏操作压力。
- 方便后续做多人混战和大逃杀。

PVP 的玩家决策前移到战前：

- 选择模式。
- 选择队伍。
- 选择基地宝石或 PVP 装备。
- 选择压力策略或自动施压偏好。
- 选择是否使用养成竞技队列。

局内只保留少量即时操作，第一版可以全部自动，后续再逐步开放：

- 技能自动释放。
- 战术升级自动选择。
- 压力技能自动发送或半自动发送。
- 撤离投票或撤离决策在大逃杀阶段再加入。

### 2.2 不同步弹珠逐帧

弹珠物理同步成本高，且当前战斗以本地表现为主。PVP 第一阶段不追求双方看到完全相同的弹珠轨迹。

推荐同步粒度：

- 房间状态。
- 战斗开始种子。
- 阵容快照。
- 自动升级结果。
- 技能释放事件。
- 压力发送事件。
- 当前波次、基地生命、击杀数、压力值等摘要。
- 战斗结束和结算结果。

不推荐同步：

- 每颗弹珠位置。
- 每个粒子。
- 每帧敌人坐标。
- 每次普通碰撞。

### 2.3 PVP 先做公平，再做养成

PVP 如果直接套用玩家局外养成，强玩家会压制新玩家，测试阶段也难调平。

推荐先落地公平竞技，再开放养成竞技：

- 公平竞技：所有角色、弹珠、宝石和基础协议按 PVP 标准等级计算。
- 养成竞技：保留玩家养成，但按战力分层匹配，并对过高战力做软压缩。

### 2.4 压力系统替代直接攻击

本游戏的核心爽点是打怪清场，不适合直接做角色互殴。PVP 的对抗应通过“压力”间接发生：

- 打得越快，越能给对手增加压力。
- 压力会变成额外敌人、怪物强化、Boss 强化或局内资源干扰。
- 对手承受压力越大，越容易漏怪、掉血或拖慢节奏。

这样能保留单人玩法主体，又能形成 PVP 的互动性。

## 3. 模式一：1v1 服务器压制赛

### 3.1 基本规则

1v1 服务器压制赛是第一版 PVP。

核心设定：

- 第一版由玩家进入 1v1 快速匹配，优先匹配真实玩家。
- 若 10 秒内没有真实玩家，服务端才分配服务器 AI 对手。
- 真实玩家进入同一个 PVP 关卡模板，每边有独立战场。
- 双方自动战斗。
- 双方自动选择战术升级。
- 双方通过清怪、连杀、精英击杀和 Boss 伤害积累压力。
- 压力会转化为干扰发送给对手。
- 谁先基地生命归零谁输。
- 若时间结束双方都存活，则按评分判定胜负。

建议参数：

| 项目 | 建议值 |
| --- | --- |
| 玩家人数 | 2 |
| 单局时长 | 180 秒 |
| 波数 | 10 波 |
| 默认速度 | 2x |
| 角色数量 | 3 名角色 |
| 技能释放 | 自动 |
| 战术升级 | 自动 |
| 撤离 | 第一版不开放 |
| 掉落 | 第一版只做结算奖励，不做局内保留 |

### 3.2 波次结构

PVP 不直接使用单人 20 波节奏，建议单独配置 10 波。

| 波次 | 类型 | 目的 |
| --- | --- | --- |
| 1 | 普通波 | 让双方构筑启动 |
| 2 | 普通波 + 第一次升级 | 建立第一轮差异 |
| 3 | 压力波 | 检验清场效率 |
| 4 | 精英波 + 第二次升级 | 产生第一波压力差 |
| 5 | 奖励压力波 | 给落后方追赶空间 |
| 6 | 混合波 + 第三次升级 | 放大构筑方向 |
| 7 | 高速波 | 检验控制能力 |
| 8 | 精英波 + 第四次升级 | 进入决胜前段 |
| 9 | 总攻波 | 压力集中爆发 |
| 10 | 小 Boss + 第五次升级前置 | 决出胜负 |

升级可以固定发生在第 2、4、6、8、10 波开始前，也可以按经验触发。为了 PVP 节奏稳定，第一版推荐固定波次触发。

### 3.3 自动升级规则

每次升级仍然抽 3 张战术卡，但不弹出选择面板。

自动选择方式分三层：

1. 玩家战前选择一个自动升级策略。
2. 服务端或客户端按策略给 3 张卡评分。
3. 选择分数最高的卡，并把结果作为 PVP 事件记录。

自动策略建议：

| 策略 | 选择倾向 | 适合玩家 |
| --- | --- | --- |
| 稳定防线 | 生存、控制、基地生命、减速 | 新手和防守队 |
| 极限输出 | 伤害、攻速、暴击、爆炸、连锁 | 爆发队 |
| 压力速攻 | 清怪效率、金币转伤害、精英击杀收益 | 想快速压制对手 |
| 稀有优先 | 高品质卡优先，其次看适配 | 不想细调策略 |
| 阵容适配 | 根据当前角色弹珠标签自动评分 | 推荐默认策略 |

自动评分建议：

```txt
最终分 = 品质分 + 策略分 + 阵容适配分 + 当前局势分 + 去重惩罚
```

品质分：

| 品质 | 分数 |
| --- | --- |
| 普通 | 10 |
| 稀有 | 20 |
| 史诗 | 35 |
| 传说 | 55 |

局势分示例：

- 基地生命低于 40%，生存卡 +25。
- 对手压力值领先，清场卡 +15。
- 当前波次为 Boss 波，Boss 伤害卡 +20。
- 自己已多次选择同类型卡，重复收益下降 -5 到 -20。

PVP 第一版可以复用当前自动战斗的战术评分逻辑，再加 PVP 局势项。

### 3.4 自动技能规则

第一版技能自动释放，避免操作复杂。

释放条件：

- 技能冷却完成。
- 场上敌人数量达到阈值。
- 或出现精英 / Boss。
- 或基地生命低于阈值且技能有防御效果。

不同角色可有不同释放倾向：

| 角色类型 | 释放倾向 |
| --- | --- |
| 输出角色 | 敌人密度高或 Boss 出现时释放 |
| 控制角色 | 快速怪、精英或敌人接近底线时释放 |
| 防御角色 | 基地生命下降或突破风险高时释放 |
| 经济角色 | 可击杀收益最大化时释放 |

技能释放需要进入事件流，用于对手侧摘要展示和结算校验。

## 4. 模式二：养成竞技

### 4.1 队列拆分

PVP 至少提供两个队列：

| 队列 | 是否保留养成 | 匹配依据 | 奖励定位 |
| --- | --- | --- | --- |
| 公平竞技 | 否 | 段位、隐藏分、近期胜率 | 竞技积分、段位奖励 |
| 养成竞技 | 是 | 战力、段位、近期胜率 | 更多养成资源 |

第一版建议只开放公平竞技。养成竞技作为第二阶段。

### 4.2 公平竞技规则

公平竞技统一标准：

- 所有已开放角色按 PVP 标准等级计算。
- 所有弹珠按 PVP 标准等级计算。
- 基地协议按 PVP 标准等级计算。
- 宝石可以禁用，或统一为标准宝石模板。
- 角色是否拥有可保留，也可以开放本周免费轮换。

推荐第一版：

- 玩家只能使用自己拥有的角色。
- 角色等级统一为 10。
- 弹珠等级统一为 10。
- 基地协议统一为 0 或标准 5。
- 宝石禁用。

这样既保留收集价值，又避免养成碾压。

### 4.3 养成竞技规则

养成竞技保留玩家真实养成：

- 角色等级生效。
- 角色路线生效。
- 弹珠等级生效。
- 基地协议生效。
- 宝石生效。

但需要战力分层和软压缩：

```txt
有效属性 = PVP 基准属性 * (1 + min(养成加成, 软上限) * 压缩系数)
```

示例：

| 养成加成 | PVP 实际生效 |
| --- | --- |
| 0% - 30% | 100% 生效 |
| 30% - 80% | 50% 生效 |
| 80% 以上 | 25% 生效 |

目的：

- 养成有价值。
- 高战力有优势。
- 但不能一进场就无悬念碾压。

### 4.4 战力估算

养成竞技需要一个 PVP 战力：

```txt
PVP 战力 =
  角色战力
  + 弹珠战力
  + 基地协议战力
  + 宝石战力
  + 阵容协同战力
```

角色战力：

- 等级。
- 路线等级。
- 技能类型权重。
- 当前 PVP 环境强度修正。

弹珠战力：

- 弹珠等级。
- 伤害、冷却、控制、范围、连锁价值。
- 与角色标签匹配程度。

阵容协同：

- 是否覆盖输出、控制、生存。
- 是否存在连锁组合，例如减速 + 闪电。
- 是否极端偏科，例如全输出无防守。

战力只用于匹配和展示，不直接决定胜负。

## 5. 压力系统

### 5.1 压力定位

压力系统是 PVP 的核心交互。

它承担三件事：

- 把玩家清怪效率转化为对手可感知的威胁。
- 让自动战斗也有对抗节奏。
- 为后续大逃杀搜打撤提供“暴露、追猎、干扰、撤离”的基础。

### 5.2 压力获取

压力值来源：

| 行为 | 压力值 |
| --- | --- |
| 击杀普通敌人 | +1 |
| 击杀快速怪 / 分裂怪 | +2 |
| 击杀厚甲 / 护盾 / 治疗怪 | +3 |
| 击杀金币怪 | +2，并额外提高经济评分 |
| 击杀精英 | +18 |
| 对 Boss 造成 10% 生命伤害 | +10 |
| 10 秒内连续清怪达到阈值 | +8 |
| 比对手更早清完当前波 | +12 |
| 基地满血清波 | +5 |

压力获取要有衰减，避免滚雪球过强：

- 连续领先 3 波后，领先方压力获取 -15%。
- 落后方基地生命低于 40% 时，受到压力效果 -10%。
- 双方差距过大时，系统优先给落后方抽到防守卡。

### 5.3 压力槽

压力值进入压力槽。

建议压力槽分 3 档：

| 档位 | 消耗 | 效果定位 |
| --- | --- | --- |
| 1 档 | 30 | 小规模增援 |
| 2 档 | 60 | 怪物强化或精英干扰 |
| 3 档 | 100 | Boss 强化或强压力事件 |

第一版可以自动释放：

- 压力达到 60 自动发送 2 档。
- 如果对手基地生命低于 35%，优先发送快速突袭。
- 如果对手清怪速度很快，优先发送护盾强化。
- 如果进入 Boss 波，保留压力用于 Boss 强化。

后续可以开放战前策略：

| 施压策略 | 自动发送倾向 |
| --- | --- |
| 快速压制 | 有 1 档就发 |
| 稳定滚压 | 优先攒 2 档 |
| Boss 决胜 | 保留到 Boss 波 |
| 反制防守 | 对手领先时立即发 |

### 5.4 压力效果

第一版只做怪物相关压力，避免恶心体验。

| 压力效果 | 档位 | 说明 |
| --- | --- | --- |
| 小怪增援 | 1 | 对手下一波增加普通敌人 |
| 快速突袭 | 1 | 对手当前或下一波增加快速怪 |
| 厚甲阻塞 | 2 | 对手下一波增加厚甲怪 |
| 护盾强化 | 2 | 对手当前波部分敌人获得护盾 |
| 治疗干扰 | 2 | 对手下一波加入治疗怪 |
| 精英投放 | 3 | 对手下一波增加 1 个精英 |
| Boss 强化 | 3 | 对手 Boss 生命和护甲提升 |

暂不推荐第一版加入：

- 禁用技能。
- 减少升级选项。
- 降低玩家视野。
- 控制玩家界面。
- 夺取掉落。

这些效果容易让失败方觉得被干扰得不舒服，可以后续放进高阶模式或大逃杀道具。

### 5.5 压力防御

为了避免单向碾压，需要有防御机制：

- 生存类战术卡可以降低受到的压力。
- 控制类构筑对快速突袭更强。
- 爆炸/范围构筑对小怪增援更强。
- 护盾类基地宝石可以降低首次压力伤害。
- 落后保护降低连续压力效果。

示例：

| 防御来源 | 效果 |
| --- | --- |
| 基地护盾卡 | 下一次压力效果 -30% |
| 减速弹珠构筑 | 快速突袭怪速度 -15% |
| 爆炸弹珠构筑 | 小怪增援数量 -20% |
| 守卫者技能 | 当前波受到的压力怪生命 -10% |

## 6. 页面布局

### 6.1 总体布局

PVP 战斗页面采用横向对战布局。

顶部：

- 显示所有对战玩家头像。
- 自己头像固定在左侧或高亮。
- 对手头像按房间顺序排列。
- 多人模式下点击头像切换右侧战场。
- 头像上显示血量、状态、连线、是否淘汰。

中部：

- 左侧 2/3：玩家自己的主战场。
- 右侧 1/3：当前选中的对手战场缩略视图。

底部：

- 自己的波次、压力槽、自动策略、当前战术升级记录。
- 可选显示本局奖励预估和 PVP 积分变化。

布局示意：

```txt
+--------------------------------------------------+
| 我方头像  对手A  对手B  对手C  ...               |
| HP/波次   HP/波次 HP/波次 HP/波次                |
+----------------------------------+---------------+
|                                  |               |
|                                  | 当前选中对手   |
|       我的战场 2/3               | 战场缩略 1/3   |
|                                  |               |
|                                  |               |
+----------------------------------+---------------+
| 压力槽 | 自动策略 | 波次 | 已选升级 | 战斗摘要     |
+--------------------------------------------------+
```

### 6.2 头像区域

头像需要支持 1v1 和多人扩展。

每个头像显示：

- 头像图标。
- 昵称或短 ID。
- 基地生命条。
- 当前波次。
- 压力状态。
- 淘汰状态。
- 网络状态。

点击行为：

- 点击对手头像：右侧 1/3 战场切换为该对手。
- 点击自己头像：右侧显示自己的战斗摘要或阵容详情。
- 长按或 hover：显示对方阵容、自动策略、当前压力。

头像状态：

| 状态 | 表现 |
| --- | --- |
| 正常 | 彩色头像 |
| 当前选中 | 外框高亮 |
| 低血量 | 红色生命条闪烁 |
| 正在承压 | 压力图标闪动 |
| 已淘汰 | 灰度头像 |
| 掉线 | 断线标记 |

### 6.3 左侧主战场

主战场承担完整交互和表现：

- 完整 Canvas 战斗。
- 我方角色、弹珠、敌人、技能、掉落表现。
- 战斗 HUD 简化，避免和顶部头像重复。
- 自动升级时用短 toast 显示选中的卡。
- 压力来袭时显示压力来源和效果。

PVP 中不弹出战术选择面板。

升级展示建议：

```txt
自动升级：电弧延展
闪电连锁次数 +2
```

### 6.4 右侧对手战场

右侧战场是缩略视图，不能影响主战斗。

显示内容：

- 对手战场简化 Canvas。
- 对手敌人密度。
- 对手基地生命。
- 对手波次。
- 对手正在承受的压力。
- 对手关键技能释放。

缩略策略：

- 减少粒子数量。
- 弹珠轨迹可以简化。
- 伤害数字可以隐藏。
- 掉落表现可以隐藏。
- 重点展示敌人推进、基地受损、Boss 血量。

如果暂时无法同步对手详细战斗，第一版可用“摘要回放视图”：

- 根据对手 state digest 渲染敌人密度条。
- 显示波次进度、血量、击杀速度。
- 用简化动画表现承压。

后续再升级为真实对手战斗缩略。

### 6.5 竖屏兼容

当前游戏是竖屏 H5，PVP 横向信息更多，需要兼容两种方案。

移动端竖屏推荐：

- 顶部仍显示头像。
- 主战场占 70% 高度。
- 对手战场变成右上角或下方缩略窗。
- 点击头像切换缩略窗。

移动端横屏或桌面：

- 使用左 2/3 + 右 1/3。

CSS 断点建议：

| 宽度 | 布局 |
| --- | --- |
| 小于 760px | 上下布局，右侧战场变缩略浮层 |
| 760px - 1024px | 左 65% / 右 35% |
| 大于 1024px | 左 2/3 / 右 1/3 |

## 7. 房间与匹配

### 7.1 房间模型

PVP 需要房间层。

房间负责：

- 创建对战实例。
- 维护玩家列表。
- 维护准备状态。
- 维护模式配置。
- 下发战斗种子。
- 广播房间事件。
- 处理断线重连。

房间状态：

```txt
created -> matching -> ready -> loading -> playing -> resolving -> finished -> closed
```

玩家状态：

```txt
joined -> ready -> loading -> playing -> eliminated -> finished -> left
```

### 7.2 匹配类型

第一版支持：

- 快速匹配。
- 好友房间。
- AI 练习。

后续支持：

- 段位匹配。
- 养成竞技匹配。
- 多人大逃杀匹配。
- 自定义房间。

### 7.3 匹配规则

公平竞技匹配依据：

- 段位。
- 隐藏 MMR。
- 近期胜率。
- 等待时间。
- 网络区域。

养成竞技额外考虑：

- PVP 战力。
- 阵容强度。
- 历史异常记录。

当前 1v1 快速匹配落地规则：

- 点击开始匹配后创建服务端匹配票据。
- 0-10 秒只匹配真实玩家。
- 两个不同设备的票据进入同一队列时，立即组成真实玩家对局。
- 10 秒没有真实玩家时，服务端返回服务器 AI 兜底结果。
- 进入战斗后，真实玩家和服务器 AI 都通过快照协议驱动右侧对手战场。

后续段位匹配扩圈：

| 等待时间 | 匹配范围 |
| --- | --- |
| 0-10 秒 | 同段位、相近 MMR |
| 10-25 秒 | 放宽 1 个小段 |
| 25-45 秒 | 放宽 2 个小段，战力差提高 |
| 45 秒以上 | 提示继续等待、切换队列或进入 AI 练习 |

### 7.4 好友房间

好友房间用于测试和社交。

规则：

- 房主创建房间。
- 生成 6 位房间码。
- 其他玩家输入房间码加入。
- 房主选择模式、人数、是否公平竞技。
- 所有人准备后开始。

好友房间可以不计段位，但可给少量参与奖励。

### 7.5 AI 练习

AI 练习很适合第一阶段验证 PVP 规则。

AI 对手不需要完整服务端同步，只需要模拟：

- 固定阵容。
- 固定自动升级策略。
- 按时间生成压力。
- 按摘要生成对手状态。

用途：

- 玩家熟悉 PVP。
- 本地调参。
- 服务端房间未完成前验证玩法。

## 8. 大逃杀搜打撤模式

### 8.1 模式定位

大逃杀模式才是更完整的 PVP 搜打撤。

它不是简单多人互相淘汰，而是：

- 多名玩家进入同一局。
- 每个人有独立战场。
- 所有人都在搜资源、打怪、积累货值。
- 玩家之间可以互相施压。
- 玩家可以选择撤离，保住当前货值。
- 留到后面奖励更高，但压力和被集火风险更高。
- 最后存活或成功撤离者按货值、排名、击杀压力结算。

### 8.2 推荐人数

第一版多人扩展：

- 4 人大逃杀。

后续：

- 6 人。
- 8 人。
- 12 人限时活动。

人数越多，右侧战场切换和头像信息越重要。

### 8.3 大逃杀流程

```txt
匹配 -> 准备 -> 开局 -> 搜资源/打怪 -> 压力互投 -> 撤离窗口 -> 继续深入或撤离 -> 淘汰/撤离/最终结算
```

建议节奏：

| 时间 | 事件 |
| --- | --- |
| 0:00 | 开局，所有人进入独立战场 |
| 0:45 | 第一次资源事件 |
| 1:30 | 第一次撤离窗口 |
| 2:15 | 压力升级，允许指定目标施压 |
| 3:00 | 第二次撤离窗口 |
| 3:45 | 高价值目标暴露 |
| 4:30 | 最终撤离窗口 |
| 5:00 | 终局 Boss / 强制结算 |

### 8.4 搜打撤资源

大逃杀中资源分为：

- 临时货值：本局搜到的东西。
- 保险物品：撤离失败也能保留一部分。
- 高价值信标：拿到后收益高，但会暴露位置。
- 压力道具：可对别人发送特殊压力。
- 撤离凭证：降低撤离难度或提前撤离。

临时货值越高，玩家在头像区越显眼：

- 货值前 1 名显示金色边框。
- 持有高价值信标显示特殊图标。
- 被多人锁定时显示危险提示。

### 8.5 目标选择

多人模式下，压力可以有三种目标选择：

| 类型 | 说明 |
| --- | --- |
| 自动目标 | 系统选择当前领先者或威胁最高者 |
| 指定目标 | 玩家点击头像选择施压对象 |
| 随机目标 | 道具随机投放，适合低成本干扰 |

第一版多人建议使用自动目标，减少操作。

大逃杀成熟后再开放指定目标。

### 8.6 撤离规则

撤离窗口出现时，玩家可以选择：

- 撤离：保住当前大部分货值，结束本局。
- 继续：提高奖励倍率，但承受更多压力。

撤离不是 100% 成功，可以设计撤离战：

- 撤离时触发 20 秒防守。
- 防守成功则撤离成功。
- 防守失败则按保险规则保留部分。

撤离结果：

| 结果 | 奖励 |
| --- | --- |
| 提前撤离 | 保留 70%-90% 临时货值 |
| 深层撤离 | 保留 100% 临时货值，并有倍率 |
| 最终胜利 | 最高倍率和排名奖励 |
| 被淘汰 | 只保留保险格和少量基础奖励 |

### 8.7 大逃杀胜负

大逃杀不是只有最后存活才有收益。

排名依据：

1. 是否最终存活。
2. 是否成功撤离。
3. 撤离深度。
4. 结算货值。
5. 对其他玩家造成的压力伤害。
6. 击杀 / 淘汰贡献。

这样能让“及时撤离”成为合理策略，而不是所有人都必须打到最后。

## 9. 后端设计

### 9.1 服务端边界

PVP 服务端负责：

- 匹配。
- 房间状态。
- WebSocket 连接。
- 战斗种子和配置版本。
- 玩家阵容快照。
- 事件转发。
- 压力事件校验。
- 战斗摘要接收。
- 胜负裁决。
- 奖励发放。
- 段位和 MMR。
- 异常检测。

PVP 服务端不负责第一阶段逐帧模拟：

- 不计算每颗弹珠位置。
- 不渲染战斗。

```ts
  | { type: "state_digest"; roomId: string; hp: number; wave: number; kills: number; pressure: number; lootValue: number; timeMs: number }
  | { type: "upgrade_auto_pick"; roomId: string; wave: number; choices: string[]; picked: string; strategy: string }
  | { type: "skill_cast"; roomId: string; characterId: string; timeMs: number }
  | { type: "pressure_send"; roomId: string; targetUserId: string; pressureType: string; power: number; timeMs: number }
  | { type: "extraction_decision"; roomId: string; decision: "extract" | "continue"; timeMs: number }
  | { type: "battle_finish"; roomId: string; result: string; summary: PvpBattleSummary };
```

服务端发往客户端：

```ts
type ServerPvpEvent =

  | { type: "battle_start"; roomId: string; seed: string; configVersion: string; startsAt: number }
  | { type: "opponent_digest"; userId: string; hp: number; wave: number; kills: number; pressure: number; lootValue: number; timeMs: number }
```

### 9.5 事件序号

房间内所有服务端广播事件都带递增 `seq`。

用途：

- 断线重连时补事件。
- 避免事件乱序。
- 结算时回放关键事件。
- 检测客户端重复发送。

客户端需要记录最后处理的 `seq`。

### 9.6 断线重连

断线规则：

- 断线 10 秒内，客户端可重连并继续。
- 断线期间角色继续自动战斗，客户端重连后按服务端房间状态恢复。
- 如果断线超过 30 秒，1v1 判负或交给 AI 托管。
- 大逃杀中断线超过 30 秒视为撤离失败或淘汰，具体看模式规则。

第一版可以简单：

- 1v1 掉线 20 秒判负。
- 好友房间不计惩罚。

## 11. 结算与奖励

### 11.1 1v1 胜负

胜负优先级：

1. 对手基地生命归零，自己胜利。
2. 自己基地生命归零，自己失败。
3. 时间结束，剩余基地生命高者胜。
4. 基地生命相同，最高波次高者胜。
5. 波次相同，击杀数高者胜。
6. 击杀相同，压力有效伤害高者胜。
7. 仍相同则按总评分。

总评分：

```txt
评分 =
  剩余生命 * 1000
  + 最高波次 * 300
  + 击杀数 * 10
  + 精英击杀 * 80
  + Boss 伤害百分比 * 500
  + 有效压力 * 3
  - 承受突破 * 120
```

### 11.2 奖励

公平竞技奖励：

- 段位积分。
- 赛季币。
- 每日首胜。
- PVP 商店货币。
- 少量金币。

养成竞技奖励：

- 更多金币。
- 弹珠碎片。
- 宝石材料。
- PVP 商店货币。

大逃杀奖励：

- 临时货值兑换。
- 撤离倍率。
- 排名奖励。
- 高价值物品。
- 赛季任务进度。

### 11.3 奖励限制

防刷设计：

- 好友房间不发段位积分。
- 同一对手短时间重复匹配降低收益。
- 每日 PVP 养成奖励有上限。
- 异常标记局不发或延迟发奖励。

## 12. 竞技段位提升体系

竞技大厅不再设计独立“等级”。玩家在 PVP 中成长的主线就是段位，段位同时承担匹配分层、赛季目标、竞技商店解锁和长期荣誉展示。

段位体系要解决三个问题：

- 给玩家明确的短期目标：每局结算都能看到距离升段还差多少。
- 给匹配提供可解释分层：展示段位负责玩家感知，隐藏 MMR 负责真实强度。
- 给竞技奖励提供节制：高段位解锁更好的兑换入口，但不能让 PVP 成为必须刷的强养成来源。

### 12.1 模式独立段位

不同 PVP 模式使用不同段位，不共享积分。

| 模式 | 段位字段 | 开放阶段 | 定位 |
| --- | --- | --- | --- |
| 1v1 公平竞技 | `duel_rank` | 第一阶段 | 自动战斗压制赛主段位 |
| 1v1 养成竞技 | `power_duel_rank` | 第二阶段 | 保留养成的竞技段位 |
| 大逃杀搜打撤 | `br_rank` | 第四阶段 | 多人撤离和排名段位 |
| 好友房间 | 不计段位 | 第一阶段 | 测试、社交、练阵容 |

第一版只落地 `duel_rank`。竞技大厅可以先展示 1v1 段位，吃鸡模式卡片展示“即将开放”与未来段位名，但不产生段位数据。

### 12.2 段位结构

1v1 公平竞技推荐段位：

```txt
青铜 III -> 青铜 II -> 青铜 I
白银 III -> 白银 II -> 白银 I
黄金 III -> 黄金 II -> 黄金 I
铂金 III -> 铂金 II -> 铂金 I
钻石 III -> 钻石 II -> 钻石 I
大师
传说
```

设计规则：

- 青铜到钻石：每个大段 3 个小段，按 `III -> II -> I` 晋级。
- 每个小段需要 100 段位分。
- 小段满 100 分后进入晋级检查，满足条件立即升到下一个小段并把积分归 0。
- 大师以上不再使用小段，使用大师分和服务器排名。
- 传说为大师分排名段位，例如赛季前 500 名或大师分达到阈值且排名达标。

大逃杀模式可以使用更贴合搜打撤的段位命名，但底层仍复用同一套积分模型：

```txt
新兵 -> 猎手 -> 游侠 -> 先锋 -> 统领 -> 传奇
```

### 12.3 可见段位与隐藏 MMR

每个模式维护两套分数：

| 字段 | 作用 | 是否展示 |
| --- | --- | --- |
| `rank_tier` | 大段位，例如青铜、白银、黄金 | 展示 |
| `rank_division` | 小段位，例如 III、II、I | 展示 |
| `rank_points` | 当前小段内积分，0-100 | 展示 |
| `rank_peak` | 本赛季最高段位 | 展示 |
| `rating` | 隐藏 MMR，用于匹配和积分修正 | 不展示 |
| `placement_matches` | 定级赛剩余场次 | 可展示 |
| `win_streak` | 连胜场数 | 可展示 |
| `loss_protection` | 段位保护次数 | 可展示为保护状态 |

可见段位让玩家理解成长；隐藏 MMR 用来避免“低段高手”长期虐新，也用来让系统在等待时间变长时做更合理的扩圈。

### 12.4 定级赛

新赛季或新玩家进入某个 PVP 模式时，先进行 5 场定级赛。

定级赛规则：

- 定级赛期间仍显示临时段位，例如“定级中 2/5”。
- 定级赛可获得竞技币，但段位结算延后到第 5 场后统一确认。
- 定级结果由胜负、对手 MMR、波次表现、压力表现共同决定。
- 第一赛季第一版可以简化为：5 场后按胜场定到青铜 III 到白银 II。

定级参考表：

| 定级赛战绩 | 初始段位 |
| --- | --- |
| 0-1 胜 | 青铜 III |
| 2 胜 | 青铜 II |
| 3 胜 | 青铜 I |
| 4 胜 | 白银 III |
| 5 胜 | 白银 II |

### 12.5 单局段位分结算

1v1 公平竞技的基础积分：

| 结果 | 基础段位分 |
| --- | --- |
| 胜利 | +24 |
| 失败 | -16 |
| 掉线失败 | -24 |
| 异常对局 | 0 或延迟结算 |

最终段位分：

```txt
最终变化 =
  基础分
  + 对手强度修正
  + 连胜奖励
  + 表现修正
  + 新手保护修正
  - 异常惩罚
```

修正规则：

| 项 | 规则 |
| --- | --- |
| 对手强度修正 | 击败更高 MMR 对手额外 +2 到 +8，输给更低 MMR 对手额外 -2 到 -8 |
| 连胜奖励 | 3 连胜开始 +2，最高 +8，黄金及以下生效 |
| 表现修正 | 压力、波次、剩余生命明显优于同段平均时 +1 到 +4，只加不减 |
| 新手保护 | 青铜段失败最多 -8，前 10 场失败最多 -10 |
| 异常惩罚 | 恶意退出、重复刷同对手、疑似异常结果可扣到 -24 或冻结收益 |

第一版实现可以先只做：

| 结果 | 段位分 |
| --- | --- |
| 胜利 | +24 |
| 失败 | -12 |
| 掉线失败 | -20 |
| 3 连胜以上胜利 | 额外 +4 |
| 青铜失败 | 最多 -8 |

### 12.6 升段、降段和保护

升段规则：

- `rank_points >= 100` 时升一个小段。
- 升段后 `rank_points = rank_points - 100`，第一版可直接归 0，避免复杂溢出。
- 从大段 I 再升时进入下一大段 III，例如 `青铜 I -> 白银 III`。
- 晋级不需要额外 BO3 晋级赛，减少移动端挫败和流程中断。

降段规则：

- `rank_points <= 0` 且本局为失败时触发降段检查。
- 青铜 III 不会继续掉段。
- 低于当前小段 0 分时，降到上一个小段 75 分。
- 大段保护：每次升入新大段后获得 3 次保护，保护耗尽前不会掉回上一大段。

保护规则：

| 场景 | 保护 |
| --- | --- |
| 新玩家前 10 场 | 失败扣分降低 |
| 青铜段 | 不掉大段，扣分减半 |
| 新升大段 | 3 次大段保护 |
| 服务器异常 | 不扣段位分 |
| 对手提前掉线 | 胜方正常加分，败方按掉线规则扣分 |

### 12.7 大师和传说

大师以上更适合用排行榜驱动。

大师规则：

- 钻石 I 满 100 分后进入大师。
- 大师使用 `master_points`，不再显示小段。
- 胜负仍按 MMR 和对手强度结算，但基础分收窄，例如胜利 +12 到 +20，失败 -12 到 -22。
- 大师玩家进入赛季排行榜。

传说规则：

- 每日结算一次传说名单。
- 条件可以是 `master_points >= 500` 且排名前 500。
- 传说段位可能会因排名变化被挤回大师，但保留本赛季最高传说记录。

### 12.8 大逃杀段位积分

大逃杀不是简单胜负，段位分由名次和撤离质量决定。

大逃杀结算维度：

- 最终名次。
- 是否成功撤离。
- 临时货值。
- 击败或压制其他玩家。
- 承压生存时间。
- 是否携带高价值物品撤出。

推荐公式：

```txt
大逃杀段位分 =
  名次基础分
  + 撤离分
  + 货值分
  + 对抗分
  - 淘汰惩罚
  - 异常惩罚
```

4 人局参考：

| 结果 | 基础段位分 |
| --- | --- |
| 第 1 名且撤离 | +32 |
| 第 2 名且撤离 | +20 |
| 第 3 名且撤离 | +8 |
| 第 4 名且撤离 | 0 |
| 未撤离但存活较久 | -6 到 +4 |
| 早期淘汰 | -16 |
| 掉线 | -24 |

大逃杀段位要比 1v1 更重视“撤离成功”和“带出价值”，避免玩家只追击不搜打撤。

### 12.9 段位和竞技币奖励关系

竞技币是每局参与奖励，段位分是竞技成长奖励，两者相关但不互相替代。

1v1 公平竞技每局奖励：

| 结果 | 竞技币 | 段位分 |
| --- | --- | --- |
| 胜利 | 120+ | 增加 |
| 失败 | 45+ | 减少或保护 |
| 异常对局 | 0 或延迟发放 | 0 或延迟结算 |
| 好友房间 | 少量或 0 | 不计 |

段位对竞技商店的影响：

| 段位 | 商店解锁 |
| --- | --- |
| 青铜 | 基础竞技补给、普通碎片 |
| 白银 | 精准碎片包、低阶宝石 |
| 黄金 | 周限购高级竞技箱 |
| 铂金 | 稀有宝石材料、更多周限购次数 |
| 钻石 | 高价值外观、赛季限定兑换 |
| 大师以上 | 排行头像框、称号、纪念背景 |

高段位只解锁更多选择和轻量资源，不直接出售破坏公平的 PVP 强战力。

### 12.10 赛季周期和重置

推荐赛季周期：4 周。

赛季数据：

- 当前段位。
- 当前段位分。
- 当前隐藏 MMR。
- 本赛季最高段位。
- 本赛季胜负场。
- 本赛季最高连胜。
- 本赛季竞技币获得量。
- 赛季奖励领取状态。

赛季重置：

| 上赛季最高段位 | 新赛季初始段位 |
| --- | --- |
| 青铜 | 青铜 III |
| 白银 | 青铜 I |
| 黄金 | 白银 III |
| 铂金 | 白银 I |
| 钻石 | 黄金 III |
| 大师 | 黄金 I |
| 传说 | 铂金 III |

重置只影响段位，不清空竞技币。竞技商店可按赛季刷新限购和限定商品。

### 12.11 UI 展示

竞技大厅需要展示：

- 当前模式段位，例如 `青铜 III`。
- 段位分进度，例如 `64/100`。
- 本赛季最高段位。
- 最近 10 场胜率。
- 当前连胜。
- 今日首胜奖励状态。
- 竞技币余额。

结算页需要展示：

- 本局竞技币获得。
- 段位分变化，例如 `+24` 或 `-12`。
- 段位进度条变化。
- 升段、降段、保护触发提示。
- 影响本局积分的原因，例如“连胜 +4”“青铜保护 -4”。

匹配页需要展示：

- 当前模式段位。
- 匹配时间。
- 可选展示“正在寻找相近段位对手”，但不展示 AI 兜底细节。

### 12.12 服务端结算边界

段位必须由服务端结算，客户端只展示结果。

服务端负责：

- 根据房间结果计算段位分变化。
- 更新可见段位、隐藏 MMR、胜负场、连胜。
- 处理升段、降段和保护。
- 判断异常对局和重复匹配收益衰减。
- 返回结算明细给客户端展示。

客户端负责：

- 发起匹配时携带当前模式和本地展示信息。
- 战斗结束后提交结果摘要、快照和关键事件。
- 展示服务端返回的段位变化和奖励。

当前第一版已接入服务端权威结算接口：

- 客户端战斗结束时先用同一套公式做即时预览，避免结算页等待。
- 登录状态下，客户端调用 `POST /api/pvp/rank/finish` 提交结果摘要。
- 服务端从玩家存档读取当前段位，重新计算段位、隐藏 MMR 和竞技币。
- 服务端返回 `rankResult`、`pvpCoins` 和最新 `playerState`。
- 客户端以服务端返回为最终结果刷新本地存档和结算页。

### 12.13 数据字段

`gm_pvp_profiles` 建议按模式拆分或增加 `mode` 字段。推荐一行代表一个玩家在一个 PVP 模式下的段位档案。

| 字段 | 说明 |

| user_id | 玩家 ID |

| season_id | 当前赛季 |
| rank_tier | 大段位 |
| rank_division | 小段位 |
| rank_points | 当前小段段位分 |
| master_points | 大师以上积分 |
| rating | 隐藏 MMR |
| peak_rank_tier | 本赛季最高大段 |
| peak_rank_division | 本赛季最高小段 |
| wins | 胜场 |
| losses | 败场 |
| draws | 平局或无效局 |
| win_streak | 当前连胜 |
| best_win_streak | 本赛季最高连胜 |
| placement_matches_left | 定级赛剩余场次 |
| loss_protection | 大段保护次数 |
| last_match_id | 最近一局 |
| last_played_at | 最近 PVP 时间 |

`gm_pvp_results` 需要记录段位变化：

| 字段 | 说明 |

### 12.14 第一版落地范围

第一版落地范围：

1. 只开放 1v1 公平竞技段位。
2. 存档保存 `pvpRanks.duel`，并预留 `power_duel` 和 `battle_royale`。
3. 新玩家和新赛季进行 5 场定级赛。
4. 定级完成后按胜场落到青铜 III 到白银 II。
5. 正式对局使用胜负基础分、隐藏 MMR、连胜、表现分和新手保护综合结算。
6. 每个小段 100 分，满分自动升段，不做晋级赛。
7. 升入新大段获得 3 次大段保护。
8. 服务端重算竞技币，客户端不直接决定最终奖励。
9. 竞技大厅展示段位、进度、赛季剩余时间、胜负记录和竞技币。
10. 竞技商店商品按段位做轻量解锁。
11. 好友房间和异常对局不计段位。

第二版再加入完整 PVP 结果表、赛季奖励领取、排行榜、重复对手检测和大逃杀段位排名。

## 13. 配置设计

### 13.1 PVP 模式配置

```ts
type PvpModeConfig = {
  id: string;
  name: string;
  playerCount: number;
  queueType: "fair" | "power";
  durationMs: number;
  waveCount: number;
  speed: 1 | 2 | 4;
  autoUpgrade: boolean;
  autoSkill: boolean;
  allowExtraction: boolean;
  pressure: PvpPressureConfig;
};
```

### 13.2 PVP 波次配置

PVP 波次应独立于单人章节。

原因：

- PVP 更短。
- 节奏更密。
- 压力会改变敌人构成。
- 需要更严格的平衡。

建议新增：

```txt
src/config/pvp-modes.ts
src/config/pvp-waves.ts
src/config/pvp-pressure.ts
```

### 13.3 PVP 卡池

PVP 不一定使用完整单人卡池。

需要处理：

- 过强经济卡。
- 过强生存卡。
- 单人爽卡但 PVP 失衡的卡。
- 会造成拖局的卡。

PVP 卡池策略：

- 默认复用单人卡。
- 给每张卡增加 `pvpWeight`。
- 给部分卡增加 `disabledInPvp`。
- 给部分卡增加 `pvpEffectScale`。

示例：

```ts
type UpgradeCardPvpMeta = {
  pvpWeight?: number;
  disabledInPvp?: boolean;
  pvpEffectScale?: number;
  pvpTags?: string[];
};
```

## 14. 反作弊与校验

### 14.1 第一阶段校验

第一阶段不做完整服务端模拟，但需要基础校验：

- 战斗时间不能小于合理值。
- 波次不能超过模式上限。
- 击杀数不能超过波次理论上限。
- 压力值不能超过击杀和事件可产生的上限。
- 自动升级结果必须来自抽到的 3 张卡。
- 技能释放不能早于冷却。
- 结算奖励不能超过配置上限。

### 14.2 事件一致性

服务端记录关键事件：

- 战斗开始。
- 每次自动升级。
- 每次压力发送。
- 每次技能释放。
- 每 1-2 秒一次 state digest。
- 战斗结束。

结算时用事件粗校验：

```txt
理论压力上限 >= 客户端申报压力
理论击杀上限 >= 客户端申报击杀
技能冷却允许释放次数 >= 客户端释放次数
```

### 14.3 异常处理

异常等级：

| 等级 | 处理 |
| --- | --- |
| 轻微 | 记录 flag，正常结算 |
| 中等 | 奖励延迟发放，进入复查 |
| 严重 | 对局无效，扣除积分或封禁 |

第一版不要过度惩罚，先收集数据。

## 15. 与现有系统的关系

### 15.1 和单人战斗

PVP 复用：

- 角色配置。
- 弹珠配置。
- 敌人配置。
- 基础战斗物理。
- 自动战斗逻辑。
- 伤害和特效。
- 结算展示风格。

PVP 独立：

- PVP 波次。
- PVP 卡池权重。
- PVP 压力系统。
- PVP 房间。
- PVP 段位和奖励。
- PVP 结果接口。

### 15.2 和搜打撤

1v1 服务器压制赛不是完整搜打撤，只是 PVP 基础模式。

大逃杀才承担完整搜打撤：

- 搜：局内获取临时货值和高价值物品。
- 打：自动战斗和压力互投。
- 撤：撤离窗口、撤离战、保留货值。

### 15.3 和后端设计

现有后端第一阶段不做 PVP 是合理的。

PVP 后端应作为第二阶段扩展：

- 不影响当前账号和存档。
- 复用用户、存档、战斗记录。
- 新增 PVP 房间和赛季表。
- WebSocket 可以先作为同一个 Node 服务的模块，后续再拆独立服务。

## 16. 分阶段落地计划

### 第 0 阶段：本地 PVP 假人原型

目标：验证界面和压力是否好玩。

内容：

- 新增 PVP 战斗入口。
- 本地生成 AI 对手摘要。
- 左 2/3 自己战场，右 1/3 AI 对手摘要。
- 顶部头像区域。
- 自动升级。
- 自动技能。
- 压力槽和压力来袭。
- 本地结算。

不做：

- 真实匹配。
- WebSocket。
- 段位。
- 真实多人。

### 第 1 阶段：1v1 在线公平竞技

目标：跑通真实玩家对战。

内容：

- 快速匹配。
- 房间准备。
- WebSocket 连接。
- 同步房间状态。
- 下发种子和配置版本。
- 双方 state digest。
- 自动升级事件。
- 压力发送事件。
- 胜负结算。
- 简单战绩。

规则：

- 公平竞技。
- 统一 PVP 等级。
- 10 波。
- 180 秒。
- 不开放撤离。

### 第 2 阶段：养成竞技

目标：让局外养成进入 PVP，但不破坏公平。

内容：

- PVP 战力计算。
- 养成竞技队列。
- 战力匹配。
- 软压缩。
- 养成奖励。
- 异常检测加强。

### 第 3 阶段：多人压制赛

目标：验证多人头像和切换对手战场。

内容：

- 4 人房间。
- 顶部多头像。
- 点击头像切换右侧对手。
- 压力自动选择目标。
- 淘汰状态。
- 排名结算。

暂不做复杂撤离。

### 第 4 阶段：大逃杀搜打撤

目标：形成真正的 PVP 搜打撤。

内容：

- 临时货值。
- 高价值信标。
- 撤离窗口。
- 撤离战。
- 指定目标施压。
- 保险格。
- 撤离 / 淘汰 / 最终胜利多结果结算。
- 大逃杀赛季任务。

## 17. MVP 验收标准

第一版 1v1 PVP 验收：

- 玩家可以进入 PVP 入口并开始匹配。
- 两名玩家可以进入同一房间。
- 双方准备后同时开始战斗。
- 战斗期间无需手动选择升级。
- 系统能自动选择战术卡并显示结果。
- 顶部能显示双方头像、生命、波次。
- 左侧显示自己的完整战场。
- 右侧显示对手摘要或缩略战场。
- 点击头像可以切换右侧目标，1v1 时切换逻辑也成立。
- 双方能积累压力并对对手施压。
- 服务端能裁决胜负。
- 结算页能展示双方数据。
- 掉线和异常不会卡死房间。

## 18. 风险与注意事项

### 18.1 自动升级可能降低参与感

解决：

- 战前提供自动策略选择。
- 结算展示本局自动选择路线。
- 后续可开放“半自动策略编辑”，而不是局内手选。

### 18.2 压力过强导致滚雪球

解决：

- 压力获取衰减。
- 落后保护。
- 防守卡加权。
- 压力效果延迟到下一波，给对手反应空间。

### 18.3 右侧对手战场同步成本高

解决：

- 第一版使用摘要视图。
- 不强求对手完整轨迹。
- 逐步增加可视信息。

### 18.4 养成竞技不公平

解决：

- 先做公平竞技。
- 养成竞技独立队列。
- 战力匹配和软压缩。
- 奖励区分。

### 18.5 多人模式信息过载

解决：

- 顶部头像只显示关键状态。
- 右侧只显示一个选中对手。
- 其他玩家通过头像状态表达。
- 大逃杀中只突出高价值和危险目标。

## 19. 推荐优先实现路径

最推荐的工程路径：

1. 先做服务器 AI 对手快照，验证 UI、压力和对手战场渲染。
2. 把 PVP 波次、PVP 自动策略、PVP 压力配置独立出来。
3. 新增 PVP 战斗页面布局，不影响当前单人战斗。
4. 接入 WebSocket 房间。
5. 做 1v1 公平竞技。
6. 增加段位和战绩。
7. 做养成竞技。
8. 做 4 人多人压制赛。
9. 最后做大逃杀搜打撤。

这条路线能先把“能玩、能看、能结算”的 PVP 做出来，再逐步靠近真正的大逃杀搜打撤。

## 20. 总结

PVP 的核心形态应是：

**自动战斗 + 独立战场 + 压力互投 + 多头像观察 + 分阶段扩展到大逃杀搜打撤。**

第一版不要追求复杂操作，也不要同步每颗弹珠。让玩家在战前配置阵容和策略，局内通过自动战斗呈现构筑结果，通过压力系统形成互动，通过顶部头像和右侧战场观察对手状态。

当 1v1 稳定后，再把同一套界面和房间能力扩展到多人；当多人压制赛稳定后，再加入临时货值、撤离窗口、目标锁定和排名奖励，形成真正的 PVP 搜打撤模式。
