# 弹珠打撤搜打撤玩法优化设计

## 1. 设计目标

当前原型已经具备完整的弹珠战斗、局内升级、掉落、仓库和局外成长，但“搜打撤”中的“撤”还没有形成核心决策。现状更接近“自动打 20 波，结算时获得全部掉落”。

本方案目标是把单局循环升级为：

```txt
打怪推进 -> 搜索战利品 -> 评估风险 -> 撤离或继续深入 -> 带回养成
```

核心体验目标：

- 每 45-90 秒给玩家一次“现在走还是继续贪”的选择。
- 保留当前自动战斗和短局节奏，不把游戏改成重操作搜刮。
- 让高价值掉落在局内产生紧张感，而不是立即等同于已入库收益。
- 失败有损失，但不摧毁局外成长节奏。
- 首版改动尽量围绕现有 `session.drops`、结算、波次和 HUD 扩展。

## 2. 当前问题

### 2.1 打已经成立

现有战斗核心比较完整：

- 20 波固定流程。
- 3 名角色同时上阵。
- 每名角色自动发射 2 种弹珠。
- 局内升级三选一。
- 精英、Boss、奖励波。
- 胜利或失败结算。

这部分是“打”的主体，可以继续保留。

### 2.2 搜只有掉落表现

现有“搜”的表现包括：

- 击杀敌人概率掉落收藏品、弹珠碎片、宝石。
- 精英和 Boss 保底多次掉落。
- 局内右下角掉落背包展示本局收获。
- 结算后写入仓库。

问题是玩家没有主动搜索行为，也没有搜索代价。掉落只是一种随机奖励反馈。

### 2.3 撤缺少决策

现有结算逻辑是：

- 胜利或失败都会直接进入结算。
- 本局掉落全部写入存档。
- 失败只是金币和核心碎片少一些。

因此玩家不会产生“已经搜到好东西，要不要撤”的压力。游戏名里的“打撤”还没有机制支撑。

## 3. 核心设计

新增三套轻量系统：

1. 临时战利品
2. 撤离窗口
3. 风险热度

三者关系：

```txt
掉落进入临时背包
-> 撤离成功才完整带回
-> 继续深入提高收益倍率和热度
-> 热度提高后续战斗压力
-> 失败会损失未保险的临时战利品
```

## 4. 临时战利品

### 4.1 战利品状态

本局掉落不再默认等同于已获得。掉落进入临时背包，并拥有状态：

| 状态 | 含义 | 结算规则 |
| --- | --- | --- |
| 临时 | 本局搜到但未带回 | 撤离或通关后入库，失败时按规则损失 |
| 保险 | 放入保险格 | 失败也能带回 |
| 已带回 | 结算确认收益 | 写入仓库 |
| 损失 | 失败丢失 | 只在结算展示，不入库 |

首版可以不做“已带回”中间状态，只在结算时把临时和保险物品拆分为“带回/损失”。

### 4.2 背包容量

推荐首版加入容量，但规则要简单：

- 默认临时背包容量：18 格。
- 相同类型、相同等级的物品可堆叠，占 1 格。
- 金币和局内经验不占格。
- 收藏品、弹珠碎片、宝石占格。
- 背包满后，新掉落进入“待取舍”提示，玩家可以替换低价值物品。

如果首版想更快落地，可以先不做容量，只做保险格和失败损失。容量放到第二阶段。

### 4.3 保险格

保险格是降低挫败感的关键。

默认规则：

- 默认 1 个保险格。
- 保险格内物品失败也能带回。
- 保险格优先推荐放入高稀有度宝石、首领核心、高等级碎片。
- 局外成长可把保险格升到 3 个。

交互方式：

- 局内背包面板中，点击物品可标记为保险。
- 自动战斗开启时，系统自动保险当前最高价值物品。

## 5. 撤离窗口

### 5.1 标准模式窗口

标准 20 波模式中，在第 5、10、15 波结束后出现撤离窗口。第 20 波击败 Boss 视为完美撤离。

| 撤离点 | 名称 | 撤离结果 | 继续深入收益 | 继续深入风险 |
| --- | --- | --- | --- | --- |
| 第 5 波后 | 浅层回收 | 带回当前战利品，结算倍率较低 | 掉落价值倍率 +10% | 热度 +1 |
| 第 10 波后 | 中层撤离 | 带回当前战利品，结算倍率正常 | 掉落价值倍率 +20% | 热度 +2 |
| 第 15 波后 | 深层撤离 | 带回当前战利品，结算倍率较高 | 掉落价值倍率 +35% | 热度 +3 |
| 第 20 波后 | 完美撤离 | 带回全部战利品，通关奖励最高 | 无 | 无 |

### 5.2 撤离弹窗内容

撤离窗口展示：

- 当前临时背包货值。
- 已保险物品数量。
- 当前热度。
- 继续深入后的收益倍率。
- 继续深入后的风险变化。
- 两个按钮：`撤离带回`、`继续深入`。

文案示例：

```txt
当前货值 420
已保险 1 件
热度 2

撤离：安全带回当前战利品
继续：后续掉落价值 +20%，热度 +2
```

### 5.3 提前撤离和暂停退出

首版不建议随时撤离，避免玩家频繁打断短局节奏。

推荐规则：

- 只有撤离窗口可以安全撤离。
- 暂停菜单的“退出”视为放弃本局，只保留保险格物品和少量金币。
- 后续可以加入稀有升级卡“紧急撤离”，允许下一波结束后提前出现撤离窗口。

## 6. 风险热度

### 6.1 热度来源

热度代表玩家搜刮和深入带来的风险。

| 行为 | 热度变化 |
| --- | --- |
| 第 5 波后继续深入 | +1 |
| 第 10 波后继续深入 | +2 |
| 第 15 波后继续深入 | +3 |
| 打开高价值搜索事件 | +1 到 +2 |
| 获得传说掉落 | +1 |
| 选择贪婪类升级卡 | +1 |

### 6.2 热度效果

热度只影响后续战斗，不影响已经完成的波次。

| 热度 | 战斗变化 |
| --- | --- |
| 0 | 正常 |
| 1 | 敌人生命 +5% |
| 2 | 敌人生命 +8%，移动速度 +4% |
| 3 | 每波额外混入快速块或厚甲块 |
| 4 | 精英波额外召唤小怪，奖励波时间缩短 |
| 5 | 触底伤害 +1，Boss 生命 +12% |
| 6 | Boss 进入高压版本，掉落倍率最高 |

标准模式热度上限建议为 6。

### 6.3 热度展示

HUD 顶部新增一个紧凑显示：

```txt
热度 2
货值 420
撤离 10 波后
```

背包面板中显示更完整信息：

- 当前热度。
- 热度带来的敌人增强。
- 继续深入后的变化预览。

## 7. 搜索事件

搜索事件是第二阶段重点。首版可以先只做撤离和临时背包。

### 7.1 场上搜索目标

在奖励波、精英波、压力波中，随机出现可攻击目标：

| 目标 | 行为 | 奖励 | 风险 |
| --- | --- | --- | --- |
| 补给箱 | 固定血量，限时存在 | 收藏品、金币、保险道具 | 无或热度 +1 |
| 数据残骸 | 血量较低，但位置靠前 | 弹珠碎片、升级刷新 | 下一波敌人速度 +5% |
| 宝石矿点 | 血量较高，出现时间短 | 宝石概率高 | 热度 +1 |
| 黑箱信标 | 高价值事件入口 | 高稀有掉落 | 热度 +2，立即刷小怪 |

这些目标本质上仍是可被弹珠命中的敌对实体，复用当前碰撞和血条逻辑即可。

### 7.2 搜索选择事件

撤离窗口或奖励波后可以弹出轻量三选一：

| 选项 | 效果 |
| --- | --- |
| 稳妥回收 | 获得少量收藏品，不加热度 |
| 深度搜索 | 获得更高价值掉落，热度 +1 |
| 拆解修复 | 获得少量金币，基地生命 +1 |
| 破解黑箱 | 获得高稀有掉落，热度 +2 |
| 放弃搜索 | 无奖励，不加风险 |

不要每波都弹，避免节奏碎。建议只在奖励波和撤离窗口附近触发。

## 8. 局内升级补充

新增一组“搜打撤”相关战术升级卡。

| 卡牌 | 稀有度 | 效果 |
| --- | --- | --- |
| 压缩背包 | 普通 | 临时背包容量 +4 |
| 快速清点 | 普通 | 掉落物飞入背包速度提升，下一次搜索事件额外给 1 个普通物品 |
| 扫描协议 | 稀有 | 下一次搜索事件显示奖励品质预览 |
| 保险封装 | 稀有 | 保险格 +1，本局生效 |
| 贪婪回收 | 稀有 | 掉落概率 +25%，热度 +1 |
| 黑箱检索 | 史诗 | 下一个精英必定额外掉落 1 件高稀有物品，热度 +1 |
| 紧急撤离 | 史诗 | 下一波结束后额外出现一次撤离窗口 |
| 完美撤离 | 传说 | 当前保险格内物品复制 1 份，Boss 战前热度 -1 |

现有“完美撤离”卡现在是生存减伤效果，建议后续改名为“防线协议”，把“完美撤离”留给真正的撤离主题卡。

## 9. 结算规则

### 9.1 结算结果类型

建议把结果从 `win | lose` 扩展为：

| 结果 | 含义 |
| --- | --- |
| `extracted` | 中途撤离成功 |
| `cleared` | 第 20 波通关，完美撤离 |
| `failed` | 防线被突破或放弃 |

如果首版不想改类型，可以内部仍映射为：

- `extracted` -> `win`
- `cleared` -> `win`
- `failed` -> `lose`

但 UI 和结算文案建议先按三种结果设计。

### 9.2 奖励公式

推荐公式：

```txt
基础金币 = 击杀金币 + 波次奖励
撤离倍率 = 撤离点倍率 + 深入倍率 + 剩余生命加成
最终金币 = 基础金币 * 撤离倍率

带回掉落 = 保险物品 + 成功撤离时的临时背包物品
损失掉落 = 失败时未保险的临时背包物品
```

默认倍率建议：

| 结果 | 金币倍率 | 掉落规则 |
| --- | --- | --- |
| 第 5 波撤离 | 0.65 | 带回全部临时和保险物品 |
| 第 10 波撤离 | 0.9 | 带回全部临时和保险物品 |
| 第 15 波撤离 | 1.15 | 带回全部临时和保险物品 |
| 第 20 波通关 | 1.45 | 带回全部临时和保险物品，额外 Boss 奖励 |
| 失败 | 0.3 到 0.55 | 只带回保险物品，普通金币保底 |

失败金币倍率可以按波次提高：

```txt
失败金币倍率 = 0.25 + min(0.3, 当前波次 / 20 * 0.3)
```

这样第 18 波失败仍有一定成长收益，但未保险的高价值掉落会丢。

### 9.3 结算展示

结算界面新增：

- 撤离结果：浅层撤离 / 中层撤离 / 深层撤离 / 完美撤离 / 防线失守。
- 带回物品。
- 损失物品。
- 保险物品标记。
- 本局最高货值。
- 继续深入次数。
- 最高热度。

失败时必须清楚展示“保险物品已带回”，降低挫败感。

## 10. UI 设计

### 10.1 战斗 HUD

新增三项紧凑信息：

- 货值：当前临时背包估值。
- 热度：当前风险等级。
- 撤离：下一个撤离窗口波次。

示例：

```txt
生命 8/10 | 波次 9/20 | 货值 320 | 热度 2 | 撤离 10
```

移动端空间有限时，可以合并成一个按钮：

```txt
战利品 320 / 热度 2
```

点击打开背包面板。

### 10.2 背包面板

背包面板分区：

- 临时战利品。
- 保险格。
- 货值统计。
- 热度说明。

交互：

- 点击物品：加入或移出保险格。
- 长按或详情按钮：查看物品用途。
- 背包满时：进入替换模式。

### 10.3 撤离窗口

撤离窗口必须短、强、清楚。

布局：

```txt
撤离窗口
当前货值 420
已保险 1 件
当前热度 2

[撤离带回]
[继续深入 +20% 掉落价值 / 热度 +2]
```

如果背包里有史诗或传说物品，按钮旁提示：

```txt
有高价值物品未保险
```

## 11. 数据结构建议

### 11.1 Session 扩展

建议新增：

```ts
type ExtractionResult = "none" | "extracted" | "cleared" | "failed";

type RunLootState = {
  drops: DropEntry[];
  insuredKeys: string[];
  capacity: number;
  insuredSlots: number;
  value: number;
};

type ExtractionState = {
  result: ExtractionResult;
  depth: number;
  heat: number;
  maxHeat: number;
  nextWindowWave: number | null;
  continueBonus: number;
  extractedAtWave: number | null;
  lostDrops: DropEntry[];
};
```

`Session` 中新增：

```ts
runLoot: RunLootState;
extraction: ExtractionState;
```

首版也可以复用 `session.drops` 作为临时战利品列表，额外加：

```ts
insuredDropKeys: string[];
heat: number;
continueBonus: number;
extractedAtWave: number | null;
lostDrops: DropEntry[];
```

### 11.2 SaveData 扩展

局外成长可新增：

```ts
extractionUpgrades: {
  insuredSlots?: number;
  backpackCapacity?: number;
  extractionBonus?: number;
  failureRetention?: number;
};
```

也可以先复用现有 `upgrades` 字典，新增配置项：

- `insuredSlots`
- `backpackCapacity`
- `extractionBonus`
- `failureRetention`

## 12. 后端接入

后端仍保持“客户端模拟，服务端校验结算”的边界。

`/battle/finish` payload 建议增加：

```ts
{
  resultType: "extracted" | "cleared" | "failed";
  extractedAtWave: number | null;
  heat: number;
  maxHeat: number;
  continueCount: number;
  securedDrops: DropEntry[];
  lostDrops: DropEntry[];
  insuredDrops: DropEntry[];
}
```

服务端校验重点：

- 撤离波次必须是允许窗口：5、10、15、20。
- 失败不能带回未保险临时物品。
- 热度和继续次数不能超过配置上限。
- 掉落总量不超过当前波次、热度、敌人击杀数允许的上限。
- 保险格数量不能超过玩家局外等级和本局升级卡效果。

## 13. 分阶段落地

### 13.1 MVP 阶段

目标：最快让“撤”变成真实选择。

实现内容：

1. 第 5、10、15 波结束出现撤离窗口。
2. 继续深入增加掉落/金币倍率和热度。
3. 失败时只保留保险格物品和部分金币。
4. 右下角背包显示货值、保险格和热度。
5. 结算展示带回和损失。

暂不做：

- 背包容量。
- 场上搜索目标。
- 搜索选择事件。
- 复杂后端重算。

### 13.2 第二阶段

目标：让“搜”从随机掉落变成主动行为。

实现内容：

1. 奖励波出现补给箱和数据残骸。
2. 搜索事件三选一。
3. 背包容量和替换。
4. 新增搜索/撤离主题升级卡。

### 13.3 第三阶段

目标：形成长期可扩展的搜打撤模式。

实现内容：

1. 无尽模式接入撤离窗口。
2. 首领挑战加入专属搜索事件。
3. 高热度 Boss 版本。
4. 后端按配置版本校验掉落上限。
5. 局外撤离科技树。

## 14. 平衡参数初稿

### 14.1 撤离倍率

| 撤离点 | 金币倍率 | 掉落价值倍率 |
| --- | --- | --- |
| 5 | 0.65 | 1.0 |
| 10 | 0.9 | 1.1 |
| 15 | 1.15 | 1.25 |
| 20 | 1.45 | 1.45 |

### 14.2 继续深入奖励

| 继续点 | 后续金币倍率 | 后续掉落权重 | 热度 |
| --- | --- | --- | --- |
| 5 -> 10 | +10% | 稀有权重 +8% | +1 |
| 10 -> 15 | +20% | 稀有权重 +14% | +2 |
| 15 -> 20 | +35% | 稀有权重 +22% | +3 |

### 14.3 失败保留

| 失败波次 | 金币保留 | 掉落保留 |
| --- | --- | --- |
| 1-4 | 25% | 保险格 |
| 5-9 | 35% | 保险格 |
| 10-14 | 45% | 保险格 |
| 15-19 | 55% | 保险格 |
| 20 Boss 失败 | 60% | 保险格，另保留 1 件最高价值非保险物品 |

## 15. 验收标准

MVP 完成后应满足：

- 玩家在第 5、10、15 波至少会看到一次明确撤离选择。
- 玩家能在战斗中看到当前货值和风险。
- 玩家失败后能理解哪些物品带回、哪些损失。
- 高价值掉落会改变玩家的撤离意愿。
- 单局平均时长仍保持在 3-5 分钟。
- 不登录后端时，本地模式仍能完整运行。

## 16. 风险与注意事项

- 失败损失不能过重，否则轻度 H5 玩家会流失。
- 撤离弹窗不能太频繁，否则破坏弹珠清场爽感。
- 热度增强要可感知但不要数值碾压。
- 背包容量建议第二阶段再做，避免首版交互负担过高。
- 后端未完成强校验前，不要把高价值活动奖励完全依赖客户端上报。

## 17. 推荐优先实现路径

建议先做最小闭环：

```txt
撤离窗口
-> 继续深入倍率和热度
-> 保险格
-> 失败损失
-> 结算展示
```

这条路径改动少，但能立刻让游戏从“打完拿奖励”变成“搜到东西后决定撤不撤”。
