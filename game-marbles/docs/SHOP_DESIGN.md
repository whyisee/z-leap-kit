# 补给商店模块设计

## 1. 模块定位

商店在当前版本命名为 **补给站**。它不是付费商城，而是局外养成的资源调度入口，主要解决三件事：

- 给金币一个稳定消耗出口，避免只堆在角色和基地协议上。
- 给弹珠碎片、低级宝石提供定向获取方式，降低纯随机掉落带来的卡进度。
- 给每日登录和重复挑战提供轻量奖励反馈，让玩家回基地时有可点内容。

首版已经完成免费补给、金币碎片货架和低级宝石集市。下一阶段需要从“补给柜”升级为“商场”，并接入高级货币 **能源晶体**。能源晶体用于充值兑换获取，承担高级解锁、外观、限量礼包和长期运营内容，不应该无限制直接出售顶级战力。

## 2. 当前资源约束

已有资源：

| 资源 | 当前来源 | 当前用途 | 商店设计中的作用 |
| --- | --- | --- | --- |
| 金币 | 战斗结算、收藏品出售、经济升级 | 角色等级、基地协议 | 主消费货币 |
| 能源晶体 | 充值兑换、运营赠送少量体验 | 高级解锁、高级礼包、外观和服务型内容 | 高级消费货币 |
| 弹珠碎片 | 战斗掉落、撤离奖励 | 升级对应弹珠 | 可定向购买少量 |
| 宝石 | 精英/Boss 掉落、撤离奖励 | 装备基地槽、合成 | 可购买低级或限量宝石 |
| 收藏品 | 掉落、撤离奖励 | 出售换金币、部分角色解锁 | 不直接出售高稀有收藏品，避免破坏解锁 |

商店原则：

- 不能直接卖高等级终局强度。
- 不能让商店替代战斗掉落。
- 允许玩家用金币补齐短板，但价格要高于战斗平均收益。
- 每日免费奖励要小而明确，鼓励回访，不制造强压力。
- 能源晶体可以加速成长和解锁高级内容，但高级战力必须有周/月限购或可通过玩法长期获得的替代路径。
- 避免把核心弹珠碰撞爽感、基础通关能力和关键角色完全锁进付费。

## 3. 页面结构

补给站首页采用三段式：

1. 顶部资源栏
   - 显示金币、今日免费状态、下次刷新时间。
   - 快捷入口：前往仓库、前往弹珠库。

2. 货架标签
   - 每日补给
   - 弹珠碎片
   - 宝石集市
   - 特惠包

3. 商品列表
   - 每个商品是独立卡片。
   - 卡片显示图标、名称、内容、价格、库存、购买按钮。
   - 已售罄置灰，不从列表消失，避免布局跳动。

建议首屏优先展示：

- 每日免费补给。
- 3 个今日推荐商品。
- 下方再进入分类货架。

## 4. 货架设计

### 4.1 每日补给

目标：提供稳定回访奖励，并让玩家理解商店价值。

商品：

| 商品 | 内容 | 价格 | 限制 |
| --- | --- | --- | --- |
| 今日免费补给 | 金币 80 + 随机弹珠碎片 3 | 免费 | 每日 1 次 |
| 今日训练补给 | 金币 160 + 随机弹珠碎片 6 | 120 金币 | 每日 1 次 |
| 战术预热箱 | 下局开局经验 +8 | 180 金币 | 每日 1 次，作为临时增益 |

说明：

- 免费补给首版可按本地日期刷新。
- 如果后端可用，刷新状态应由服务端计算，避免改本地时间刷奖励。
- “下局开局经验”属于临时增益，首版可以先不做购买，保留为后续商品。

### 4.2 弹珠碎片货架

目标：给某个弹珠差几片升级时提供补齐手段。

商品池：

| 商品 | 内容 | 基础价格 | 库存 |
| --- | --- | --- | --- |
| 基础弹珠碎片 | basic 碎片 x8 | 120 金币 | 每日 2 次 |
| 分裂弹珠碎片 | split 碎片 x6 | 150 金币 | 每日 2 次 |
| 爆裂弹珠碎片 | blast 碎片 x6 | 160 金币 | 每日 2 次 |
| 燃烧弹珠碎片 | burn 碎片 x6 | 150 金币 | 每日 2 次 |
| 闪电弹珠碎片 | lightning 碎片 x6 | 170 金币 | 每日 2 次 |
| 减速弹珠碎片 | slow 碎片 x6 | 150 金币 | 每日 2 次 |

动态价格建议：

```txt
实际价格 = 基础价格 * (1 + 当前弹珠等级 * 0.08)
```

理由：

- 高等级时仍能补齐，但不会比正常刷关更划算。
- 低等级玩家可以更快完成第一次升级，减少卡顿。

首版展示策略：

- 每天随机出现 3 种弹珠碎片。
- 优先提高玩家当前最低等级弹珠的出现权重。
- 已满级弹珠不进商品池。

### 4.3 宝石集市

目标：补充低级宝石来源，服务基地宝石槽和合成系统。

商品池：

| 商品 | 内容 | 价格 | 库存 |
| --- | --- | --- | --- |
| 强袭宝石原胚 | 强袭宝石 Lv.1 x1 | 220 金币 | 每日 1 次 |
| 壁垒宝石原胚 | 壁垒宝石 Lv.1 x1 | 220 金币 | 每日 1 次 |
| 回收宝石原胚 | 回收宝石 Lv.1 x1 | 240 金币 | 每日 1 次 |
| 随机宝石箱 | 随机 Lv.1 宝石 x1，10% 为 Lv.2 | 320 金币 | 每日 1 次 |

限制：

- 首版只卖 Lv.1，随机箱低概率 Lv.2。
- 不直接出售 Lv.3+，避免破坏精英/Boss 掉落价值。
- 玩家宝石总数过多时不禁止购买，但卡片提示“可前往仓库合成”。

### 4.4 特惠包

目标：做成“金币换组合资源”的轻度选择，不做真实付费特惠。

商品：

| 商品 | 内容 | 价格 | 库存 | 解锁条件 |
| --- | --- | --- | --- | --- |
| 新手整备包 | 金币 100 + 基础碎片 x10 + 强袭宝石 Lv.1 | 260 金币 | 账号 1 次 | 默认 |
| 反弹构筑包 | 基础碎片 x8 + 分裂碎片 x8 | 360 金币 | 每周 1 次 | 通关 1-3 |
| 爆破构筑包 | 爆裂碎片 x8 + 燃烧碎片 x8 | 390 金币 | 每周 1 次 | 通关 2-1 |
| 控制构筑包 | 闪电碎片 x8 + 减速碎片 x8 | 400 金币 | 每周 1 次 | 通关 2-5 |
| 回收构筑包 | 回收宝石 Lv.1 + 随机收藏品 x1 | 480 金币 | 每周 1 次 | 通关 1-6 |

注意：

- “金币 100 + 资源”这种包看起来返金币，但净消耗仍然为价格减返还。
- 随机收藏品只给普通/稀有，不给 `void_lens` 和 `boss_core`，避免绕过角色解锁和 Boss 价值。

## 5. 刷新机制

首版推荐三类刷新：

| 刷新类型 | 范围 | 成本 |
| --- | --- | --- |
| 每日刷新 | 免费补给、碎片货架、宝石集市库存 | 每日 0 点 |
| 手动刷新 | 只刷新碎片货架 3 个商品 | 80 金币，逐次 +60，当日最多 3 次 |
| 周刷新 | 特惠包库存 | 每周一 0 点 |

本地原型阶段可以用日期字符串作为刷新键：

```txt
dailyKey = YYYY-MM-DD
weeklyKey = YYYY-WW
```

后端接入后，商店库存和购买记录应以服务端时间为准。

## 6. 购买与库存规则

购买流程：

1. 点击商品卡片购买按钮。
2. 校验商品是否解锁、是否售罄、金币是否足够。
3. 扣除金币。
4. 发放物品到对应背包：
   - 金币：`save.coins`
   - 弹珠碎片：`save.inventory.marbleShards`
   - 宝石：`save.inventory.gems`
   - 收藏品：`save.inventory.collectibles`
   - 临时增益：后续新增 `save.shopBuffs` 或 `preferences` 外的运行态字段。
5. 更新库存计数。
6. 保存存档。
7. 卡片显示“已购买”或剩余库存。

错误提示：

| 场景 | 提示 |
| --- | --- |
| 金币不足 | 金币不足，可通过闯关或出售收藏品获得 |
| 已售罄 | 今日库存已售罄 |
| 未解锁 | 通关指定关卡后解锁 |
| 满级弹珠 | 该弹珠已满级，不再出售碎片 |

## 7. 商店数据结构建议

商品定义：

```ts
type ShopCategory = "daily" | "shards" | "gems" | "bundles";

type ShopItemConfig = {
  id: string;
  category: ShopCategory;
  name: string;
  desc: string;
  price: number;
  stock: number;
  refresh: "daily" | "weekly" | "once";
  unlock?: {
    type: "stage" | "wins";
    value: number;
  };
  rewards: ShopReward[];
};

type ShopReward =
  | { type: "coins"; amount: number }
  | { type: "marbleShard"; marbleId: MarbleId; amount: number }
  | { type: "gem"; gemType: GemType; level: number; amount: number }
  | { type: "collectible"; collectibleId: CollectibleId; amount: number };
```

存档状态：

```ts
type ShopState = {
  dailyKey: string;
  weeklyKey: string;
  purchased: Record<string, number>;
  manualRefreshCount: number;
  shardOfferIds: string[];
};
```

首版可以把 `ShopState` 挂到 `SaveData.shop`：

```ts
type SaveData = {
  ...
  shop: ShopState;
};
```

兼容旧存档时，缺失 `shop` 自动初始化。

## 8. 首版 MVP 范围

建议第一阶段只做这些，闭环最清楚：

1. 商店页面从占位改成完整补给站。
2. 增加 `shop` 存档字段。
3. 每日免费补给：
   - 金币 80。
   - 随机弹珠碎片 3。
   - 每日 1 次。
4. 弹珠碎片货架：
   - 每日随机 3 个弹珠碎片商品。
   - 支持金币购买。

5. 宝石集市：
   - 3 个 Lv.1 宝石商品。
   - 每日各 1 次。
6. 购买后写入现有背包和金币。
7. 商店卡片有已售罄、金币不足、未解锁状态。

第二阶段再做：

- 周特惠包。
- 构筑推荐包。
- 下局临时增益。
- 服务端商店库存和购买校验。
- 活动商店。

## 10. 平衡建议

价格基准：

| 玩家阶段 | 单局金币预期 | 商店体验 |
| --- | --- | --- |
| 1 章前期 | 120-300 | 能买 1 个低级碎片商品 |
| 1 章后期 | 300-700 | 能买 1-2 个商品，仍需取舍 |
| 2-3 章 | 700-1500 | 可买宝石原胚或构筑包 |
| 4-5 章 | 1500+ | 商店用于补齐和合成，不替代刷 Boss |

初始价格不要太低：

- 碎片商品低于 100 会过快压缩战斗掉落价值。
- 宝石原胚低于 200 会让精英/Boss 掉落不够兴奋。
- 手动刷新成本要能感知，但不应高到完全没人点。

## 11. 与现有模块关系

| 模块 | 关系 |
| --- | --- |
| 仓库 | 购买结果进入仓库；宝石可继续装备/合成 |
| 弹珠库 | 碎片购买后可立即去升级弹珠 |
| 角色 | 不直接卖角色；只通过资源间接帮助养成 |
| 战斗 | 商店不影响单局实时战斗，除非后续加入临时增益 |
| 后端 | 长期应校验购买、刷新和每日补给，防止本地篡改 |

## 12. 开发拆分

推荐文件：

```txt
src/config/shop.ts
src/systems/shop/offers.ts
src/systems/shop/purchase.ts
src/ui/menu/shop.ts
src/styles/shop.css
```

如果暂时不拆 `main.ts`，也建议至少先把配置放入 `src/config/shop.ts`，避免商品内容写死在页面 HTML 里。

开发顺序：

1. 类型和默认存档：`ShopState`、`ShopItemConfig`。
2. 商品配置：每日补给、碎片、宝石。
3. 生成每日货架：按日期和存档生成稳定商品。
4. 购买逻辑：扣金币、发奖励、扣库存。
5. 页面渲染：分类、商品卡、状态提示。
6. 刷新逻辑：手动刷新碎片货架。
7. 本地验证：领取、购买、刷新、重载页面后状态保留。

## 13. 商场升级方向

当前商店的问题不是商品少，而是缺少明确分层：

- 玩家不知道每天应该买什么。
- 金币商品和宝石商品看起来都像普通列表，缺少“今日推荐”和成长目标。
- 没有高级货币消费场景，能源晶体即使加入也没有合理出口。
- 没有账号级长期目标，例如外观、特权、赛季奖励、章节礼包。

建议把商场拆成 6 个货架：

| 货架 | 货币 | 定位 | 商品特点 |
| --- | --- | --- | --- |
| 推荐 | 金币 / 能源晶体 | 首屏导购 | 每日免费、缺口补齐、限时礼包 |
| 日常补给 | 免费 / 金币 | 低压力回访 | 免费补给、金币补给、训练补给 |
| 成长材料 | 金币 | 常规养成 | 弹珠碎片、低级宝石、少量收藏品 |
| 晶体商店 | 能源晶体 | 高级消费 | 角色提前解锁、精选箱、保险券、改名/服务 |
| 外观商店 | 能源晶体 | 付费主力 | 角色皮肤、弹珠轨迹、基地外观、击中特效 |
| 限时礼包 | 能源晶体 | 运营活动 | 新手、章节通关、周/月限购、节日礼包 |

首屏不建议让玩家直接进入长列表。推荐页应该根据玩家状态展示 4-6 个商品：

- 免费补给可领取。
- 当前最低等级弹珠的碎片。
- 当前缺少的 Lv.1 宝石。
- 章节通关礼包。
- 角色提前解锁或外观推荐。
- 能源晶体余额和充值入口。

## 14. 货币体系

### 14.1 金币

金币继续作为免费软货币：

- 来源：闯关、撤离、收藏品回收、活动。
- 用途：角色等级、技能升级、基地协议、日常补给、碎片补齐。
- 商店消费感：帮助补短板，但不能替代刷关。

### 14.2 能源晶体

能源晶体作为高级货币：

- 来源：充值兑换为主；活动、维护补偿、成就可少量赠送。
- 用途：高级解锁、外观、限量礼包、便利型服务、赛季通行证。
- 不建议用途：无限购买顶级宝石、无限购买高等级弹珠碎片、直接购买通关。

推荐消费边界：

| 可用能源晶体购买 | 设计说明 |
| --- | --- |
| 角色提前解锁 | 付费提前拥有，但玩家仍可通过关卡/成就解锁 |
| 角色皮肤 | 最适合晶体消费，不破坏数值平衡 |
| 弹珠轨迹/命中特效 | 强化弹珠游戏辨识度 |
| 基地外观 | 商场展示价值高，不影响战斗强度 |
| 精选材料箱 | 周/月限购，提供低中等级资源 |
| 保险券 | 搜打撤主题强，但必须限量，避免付费无脑保底 |
| 赛季通行证 | 长期目标，奖励包含外观和材料 |
| 改名/头像框/资料背景 | 服务型和装饰型消费 |

不建议直接售卖：

- 传说宝石高等级成品。
- 无限首领核心。
- 无限复活。
- 只能付费获得且明显高强度的角色。
- 无限制掉落倍率。

## 15. 能源晶体商品设计

### 15.1 充值兑换入口

充值入口独立于商品货架，建议命名为“能源补充”。

展示内容：

- 当前能源晶体余额。
- 充值档位。
- 首充奖励状态。
- 充值记录入口。

档位不要写死在前端逻辑里，后续应由后端配置下发。

示例档位：

| 档位 | 获得能源晶体 | 首次额外 |
| --- | --- | --- |
| 微型能源包 | 60 | +60 |
| 小型能源包 | 300 | +300 |
| 标准能源包 | 980 | +980 |
| 大型能源包 | 1980 | +1980 |
| 核心能源包 | 3280 | +3280 |
| 旗舰能源包 | 6480 | +6480 |

首充双倍只建议每档一次。后续可做活动加赠，但必须由服务端控制。

### 15.2 角色提前解锁

角色可以通过两条路径获得：

- 免费路径：通关、胜场、收藏品解锁。
- 晶体路径：提前解锁。

示例：

| 商品 | 内容 | 能源晶体 | 限制 |
| --- | --- | --- | --- |
| 霜语者授权 | 提前解锁霜语者 | 300 | 未拥有时可买 |
| 虚空使授权 | 提前解锁虚空使 | 680 | 未拥有时可买 |
| 财宝猎人授权 | 提前解锁财宝猎人 | 680 | 未拥有时可买 |

如果玩家之后通过免费路径也达到条件，不返还晶体；购买前要明确提示“提前解锁”。

### 15.3 外观内容

外观是能源晶体的主要长期消耗点。

推荐外观类型：

| 类型 | 示例 | 价格区间 |
| --- | --- | --- |
| 角色皮肤 | 工程师·极地维修、爆破手·熔火工装 | 300-980 |
| 弹珠轨迹 | 星轨、火花、数据流、冰晶 | 180-480 |
| 击中特效 | 像素爆点、雷弧扩散、金币飞溅 | 180-480 |
| 基地外观 | 旧城车间、磁轨平台、熔炉甲板 | 480-1280 |
| 头像框 | 首领核心、通关纪念、赛季徽记 | 120-360 |

外观原则：

- 不附带战斗数值。
- 可以附带极小展示型属性，例如收藏评分，但不进入战斗公式。
- 商店卡片应支持预览。

### 15.4 高级材料箱

高级材料箱可以卖，但要限购。

| 商品 | 内容 | 能源晶体 | 限制 |
| --- | --- | --- | --- |
| 精选弹珠箱 | 选择一种弹珠碎片 x30 | 120 | 每周 3 次 |
| 宝石原胚箱 | 自选 Lv.1 宝石 x2 | 160 | 每周 3 次 |
| 稀有宝石箱 | 随机 Lv.2 宝石 x1 | 260 | 每周 2 次 |
| 首领材料箱 | 随机稀有收藏品 x2，不含首领核心 | 180 | 每周 2 次 |
| 深层撤离箱 | 保险券 x2 + 随机碎片 x20 | 220 | 每周 2 次 |

注意：

- 宝石最多卖到 Lv.2，Lv.3+ 仍依赖战斗、合成和 Boss。
- 收藏品箱不直接给 `boss_core`，首领核心应该保留 Boss 价值。
- 自选箱优于随机箱，减少抽奖感。

### 15.5 保险券和撤离道具

“搜打撤”玩法适合做有限的高级便利道具。

| 道具 | 效果 | 获取 |
| --- | --- | --- |
| 保险券 | 本局额外保险 1 件掉落 | 活动、晶体周限购 |
| 撤离信标 | 下一个撤离窗口提前显示奖励预估 | 活动、金币/晶体少量 |
| 战术扫描 | 下一次升级选项额外刷新 1 次 | 活动、晶体限购 |

限制：

- 单局保险券最多生效 1 次。
- 保险券不能保护所有掉落。
- 不能做“失败后消耗晶体直接保留全部战利品”。

## 16. 礼包体系

礼包分三类：

### 16.1 新手礼包

目标：给新玩家一个可理解的低价入口。

| 商品 | 内容 | 货币 |
| --- | --- | --- |
| 新手整备包 | 强袭宝石 Lv.1、基础碎片 x20、金币 300 | 能源晶体 |
| 七日补给证 | 连续 7 天领取金币、碎片、少量晶体返还 | 能源晶体 |

### 16.2 章节礼包

目标：玩家通关关键节点后出现，奖励和章节主题匹配。

| 解锁节点 | 礼包内容 |
| --- | --- |
| 通关 1-5 | 基础/分裂碎片、强袭宝石 |
| 通关 2-5 | 闪电/减速碎片、壁垒宝石 |
| 通关 3-5 | 爆裂/燃烧碎片、回收宝石 |
| 通关 5-10 | 全类型碎片、自选 Lv.2 宝石、限定头像框 |

### 16.3 周/月礼包

目标：稳定长期消费，但不无限堆战力。

| 商品 | 内容 | 限制 |
| --- | --- | --- |
| 周材料补给 | 自选碎片、Lv.1 宝石、金币 | 每周 1 次 |
| 月度整备包 | 自选 Lv.2 宝石、保险券、外观券 | 每月 1 次 |
| 赛季支援包 | 通行证经验、碎片、头像框 | 每赛季 1 次 |

## 17. 赛季通行证

建议做“赛季补给证”，比直接卖战力更健康。

结构：

- 免费线：金币、碎片、低级宝石、保险券少量。
- 高级线：外观、头像框、更多自选材料、能源晶体返还。
- 任务来源：每日登录、完成闯关、撤离成功、击败 Boss、收集掉落价值。

奖励比例：

- 免费线给 35%-45% 总奖励。
- 高级线给 55%-65% 总奖励，其中至少一半是外观或选择箱。
- 高级线不提供无法通过玩法获得的纯数值优势。

## 18. UI 升级方案

商场不应继续只有 4 个小标签。建议新版结构：

```txt
┌──────────────────────────────┐
│ 补给商场   金币 4309  晶体 680│
├──────────────────────────────┤
│ 今日推荐                       │
│ [免费补给] [最低等级碎片]      │
│ [章节礼包] [角色授权/外观]     │
├──────────────────────────────┤
│ 推荐 日常 成长 晶体 外观 礼包  │
├──────────────────────────────┤
│ 商品列表                       │
└──────────────────────────────┘
```

视觉重点：

- 顶部同时显示金币和能源晶体。
- 能源晶体商品使用独立色彩，例如青紫色，不和金币混淆。
- 商品卡明确标识货币图标。
- 晶体商品必须显示限购和是否永久解锁。
- 外观商品提供预览按钮。
- 推荐页优先展示“可领取”和“缺口补齐”。

## 19. 数据结构调整建议

当前 `ShopItemConfig.price` 是单个数字，只适合金币。需要改成多货币价格。

建议：

```ts
type CurrencyId = "coins" | "energyCrystals";

type ShopPrice = {
  currency: CurrencyId;
  amount: number;
};

type ShopItemConfig = {
  id: string;
  category: ShopCategory;
  name: string;
  desc: string;
  price: ShopPrice;
  stock: number;
  refresh: ShopRefreshType;
  purchaseLimit?: "daily" | "weekly" | "monthly" | "once";
  tags?: Array<"recommended" | "premium" | "cosmetic" | "growth" | "limited">;
  rewards: ShopReward[];
};
```

奖励也需要扩展：

```ts
type ShopReward =
  | { type: "coins"; amount: number }
  | { type: "energyCrystals"; amount: number }
  | { type: "marbleShard"; marbleId: MarbleId; amount: number }
  | { type: "gem"; gemType: GemType; level: number; amount: number }
  | { type: "characterUnlock"; characterId: string }
  | { type: "skin"; skinId: string }
  | { type: "cosmetic"; cosmeticId: string }
  | { type: "ticket"; ticketId: "insurance" | "scan" | "refresh"; amount: number };
```

存档需要新增：

```ts
type SaveData = {
  coins: number;
  energyCrystals: number;
  ownedSkins: string[];
  ownedCosmetics: string[];
  tickets: Record<string, number>;
  shop: ShopState;
};
```

能源晶体充值和消费长期必须服务端权威：

- 充值成功由服务端增加晶体。
- 消费晶体由服务端扣减并写流水。
- 客户端本地只做展示和离线原型，不能作为真实晶体余额依据。

## 20. 迭代建议

建议按三步走：

### 第一阶段：商场变丰富，但仍本地

- 顶部显示金币 + 能源晶体。
- 商品支持 `coins` / `energyCrystals` 双货币。
- 新增推荐页、晶体页、礼包页。
- 先给测试存档少量能源晶体，不接真实充值。
- 实现角色提前解锁、精选材料箱、保险券。

### 第二阶段：高级内容闭环

- 增加外观数据结构和外观预览。
- 增加角色皮肤、弹珠轨迹、基地外观。
- 增加周礼包和章节礼包。
- 增加限购状态和月刷新。

### 第三阶段：服务端充值与运营

- 服务端维护能源晶体余额。
- 接支付订单、充值档位、首充状态。
- 所有晶体消费写 `currency_ledger`。
- 活动和礼包配置由服务端下发。
- 客户端只渲染服务端返回的可售商品。
