# 基地主页 UI 改版方案

## 背景

当前基地主页主要围绕一个战斗入口组织内容，角色、仓库、商店、弹珠、基地协议等系统更多依赖顶部小图标或底部导航进入。这样会让主页更像一个启动页，而不是一个可经营、可成长的游戏基地。

本次优化目标是把主页改成“基地大厅”：战斗入口仍然是最高优先级，但其他核心养成系统也要以清晰、有游戏感的功能入口出现在首屏。

## 设计目标

- 让玩家进入主页时能立刻看见多个可操作系统，而不是只看见“开始战斗”。
- 把普通 App 风格按钮改成游戏设施入口，减少出戏感。
- 保持战斗入口最突出，同时让角色、弹珠、仓库、商店、基地协议都有明确位置。
- 用统一风格的素材承载功能入口，避免纯 CSS 方块按钮。
- 保留底部导航作为快捷切换，但主页的主要表达由“基地功能区”承担。

## 页面结构

推荐结构如下：

```text
顶部区域：用户资料 / 资源状态 / 设置与辅助入口
中上区域：出阵小队站台
中心区域：作战终端，展示当前章节、关卡、战力、收益、开始战斗
下方区域：基地功能入口矩阵
底部区域：现有主导航，作为快捷栏
```

## 首屏功能入口

主页建议放置 7 个核心入口，每个入口使用“设施素材 + 铭牌文字”的形式。

| 功能 | 入口名称 | 目标页面 | 素材方向 | 交互重点 |
| --- | --- | --- | --- | --- |
| 战斗 | 作战终端 | 开始战斗 / 选关 | 发光传送门、战术地图、启动核心 | 最大入口，显示当前关卡和开始按钮 |
| 角色 | 编队舱 | 角色页面 | 三个角色站台、舱门、队伍剪影 | 显示出阵人数和可培养提示 |
| 弹珠 | 弹珠工坊 | 弹珠库 | 机械工坊、旋转弹珠、能量轨道 | 显示可升级弹珠数量 |
| 仓库 | 仓储库 | 仓库页面 | 宝箱、货架、发光宝石箱 | 显示物品数量和可回收价值 |
| 商店 | 补给站 | 商店页面 | 自动贩卖机、补给箱、金币终端 | 显示可领取或可购买状态 |
| 基地 | 基地中枢 | 基地协议 | 能量核心、芯片控制台 | 显示可升级协议数量 |
| 外观 | 幻化舱 | 幻化抽卡 / 外观管理 | 展示舱、换装镜面、星盒彩球、弹珠投影 | 显示免费抽、保底接近、可兑换状态 |

挑战任务可以作为第 8 个入口，也可以放在作战终端旁边作为副入口；排行、引导、设置更适合保留在顶部辅助区。

## 素材清单

建议新增一组统一风格的 PNG 或 WebP 素材：

- `src/assets/home/home-hub-background.webp`：基地大厅背景，中央留出作战终端区域。
- `src/assets/home/entry-battle-terminal.png`：作战终端。
- `src/assets/home/entry-heroes-bay.png`：编队舱。
- `src/assets/home/entry-marble-workshop.png`：弹珠工坊。
- `src/assets/home/entry-inventory-vault.png`：仓储库。
- `src/assets/home/entry-shop-station.png`：补给站。
- `src/assets/home/entry-protocol-core.png`：基地中枢。
- `src/assets/home/entry-cosmetic-chamber.png`：幻化舱。
- `src/assets/home/entry-challenge-board.png`：挑战任务板，可选。

素材风格建议：

- 半卡通科幻基地风，和当前角色素材、底部导航素材保持同一方向。
- 透明背景 PNG 用于入口设施，WebP 用于大背景。
- 每个入口素材需要有清晰轮廓，避免依赖大量文字说明。
- 入口素材底部保留铭牌区域，方便叠加“编队舱”“仓储库”等短标签。
- 高亮状态用 CSS 发光和轻微位移实现，素材本身不需要生成多套状态。

## 布局方案

### 桌面宽屏

```text
┌────────────────────────────────────────────┐
│ 用户资料                  资源/排行/设置     │
├────────────────────────────────────────────┤
│ 出阵小队站台                                │
│                                            │
│              作战终端                       │
│        当前章节 / 战力 / 开始战斗            │
│                                            │
│ 编队舱   弹珠工坊   仓储库                  │
│ 补给站   基地中枢   幻化舱                  │
│ 挑战任务 / 竞技场等副入口                    │
├────────────────────────────────────────────┤
│ 底部主导航                                  │
└────────────────────────────────────────────┘
```

### 手机竖屏

```text
用户资料 / 资源
出阵小队横向小卡
作战终端大入口
功能入口 2 列网格
底部主导航
```

## 信息层级

1. 作战终端：首屏最大视觉中心，承担开始战斗。
2. 出阵小队：展示当前阵容，但不占据过多空间。
3. 功能入口矩阵：承载养成、仓库、商店、基地协议和幻化外观。
4. 顶部辅助入口：排行、引导、设置。
5. 底部导航：快捷切换，不再作为主页唯一功能入口。

## 交互细节

- 点击作战终端的主按钮直接开始战斗。
- 作战终端里的“选关”“挑战”作为小按钮或角标入口。
- 点击设施入口进入对应页面，例如仓储库进入仓库、编队舱进入角色。
- 点击幻化舱进入幻化抽卡与外观管理页面；角色详情、弹珠工坊和补给站外观货架只作为二级入口。
- 入口 hover 或按下时：设施轻微上浮、边缘发光、铭牌变亮。
- 有可升级或可领取状态时，在设施右上角显示小角标。
- 不在主页放大段说明文字，所有功能依赖图形、短标签和状态数字表达。

## 实施步骤

1. 生成并接入主页背景与入口设施素材。
2. 在 `homeMenuHtml` 中拆出功能入口数据结构，统一渲染入口矩阵。
3. 重构主页布局样式，弱化单一战斗卡片，强化基地大厅空间。
4. 给入口增加状态数字，例如可升级弹珠、仓库物品数、可回收价值。
5. 用浏览器检查桌面和移动视口，确保素材不遮挡角色、文字不溢出。

## 验收标准

- 首屏至少能看见 5 个以上明确功能入口。
- 战斗入口依然是最大、最容易点击的入口。
- 入口不再像普通 App 卡片按钮，而是像基地设施。
- 出阵角色不抢占过多空间。
- 顶部、中心、底部信息互不重叠。
- 构建通过，桌面和移动布局没有文本溢出。
