## 正文改成块编辑器（提交 d82f89e）

Z 要「飞书文档那种直接看到效果，不点预览、不显示 #」。

**关键判断：靠「淡化/透明符号」做不到飞书效果。** 列表圆点、引用左边线是块级
视觉，一个 TextField 里画不出来；而删字符又会破坏光标索引。所以换模型。

- **`markdown_doc.dart`**：块是唯一真相。`MdBlockType{paragraph,h1,h2,h3,bullet,
  ordered,quote,code,divider}`，每块自带 controller + focusNode。`markdown`
  是派生 getter（序列化时才加符号），`parseMarkdown` 反向拆块。
  → 用户**打不出也看不到** `#` `-` `>` `1.` ```` ``` ````。
- 交互：打 `# `/`- `/`> `/`` ``` `` → 变块型（符号被吃掉，不进文本）；
  回车拆块；空标题/空引用回车落回正文；粘贴多行 md 走同一条 `_normalize` 递归拆。
  code 块回车不拆（代码里换行是内容），退出靠工具栏再点一次。
- 有序列表序号**不进文本**，序列化时按连续 ordered 块重排 → 插行不会错号。
- 行内 `**`/`` ` `` 拆不掉（拆了就断词），渲染成**零宽透明字符**
  （`fontSize: 0.1 + 透明`）：视觉不存在，字符仍在 → 光标索引/选区/复制都对。
  代价是光标落在隐藏符号上会变 0.1px，用 `cursorHeight`（按块型 21~30）挡住。
- **踩的坑**：
  1. `TextInputAction.newline` + `TextInputType.text` 在 maxLines>1 时被 TextField
     断言拦下 → 一律 `TextInputType.multiline`。
  2. `splitAt` 最初把 `\n` 留在后半截 → 每敲一次回车下一块开头多一个空行。
     offset 上的 `\n` 属于分隔符，两边都不留。
  3. 拆块后只 return 不处理 head，`# 标题⏎` 的 head 永远不变标题 →
     改成 `_normalize` 循环：拆完对 head 跑 `_applyPrefix`，新块继续拆。
  4. `_applyPrefix` 一开始只允许 paragraph→其它，导致 bullet 块里打 `> ` 不转 →
     放开为「除 code 块外都能转」。
  5. 程序改文本会再次触发 listener → 加 `_mutating` 重入保护；focus listener
     必须用 `Set` 去重，否则拆分一次挂一个。
  6. `charCount` 要把 `**`/`` ` `` 剔掉，否则加粗一下数字就跳。
- 测试：`markdown_doc_test`（往返无损、代码块吞掉内部 `#`、拆块不吃分隔符、
  有序列表重排）+ `markdown_editor_test`（打 `# ` 变标题且文本无井号、
  回车拆块、工具栏改块型、`**` 是 0.1px）。全量 53 过。

## 块编辑器补「行首退格删块」（提交 522bd2a）

Z 反馈「太难用了，不能删除上一个块吗」—— 这是块模型的硬伤，不是漏做按钮：
**软键盘在空文本上按退格不产生任何事件**。Flutter 引擎处理
`deleteSurroundingText` 时若删除区间为空直接 return，`onChanged` 根本不触发，
所以「空块退格」「行首退格并上一块」在纯 TextField 里无从感知。

- 解法：每块 controller 文本前面放一个零宽哨兵 `\u200B`。退格先吃掉它 →
  文本真的变短 → 事件到达。哨兵不占宽、不算字数、不进 Markdown。
- 判据不能只看「哨兵没了」（粘贴/整段替换也会没），要**同时**满足：
  曾以哨兵开头 + 变短 + 新文本是旧文本的后缀。少了后缀条件，末尾删重复字符
  （`**` → `*`）会被误判成行首删除。
- 行首退格 = 整块并进上一块，光标落拼接点（`_focusExisting` 只移焦点不动光标，
  `_focusBlock` 会强行把光标拽到行尾）。第一块没有上一块 → 补哨兵、不吃内容。
- `MdBlock` API 收敛成 `text`(剥哨兵) / `caretBase` / `caret` / `setText(v, caret:)` /
  `placeCaret` / `ensureSentinel`，所有 offset 换算走这里，别在调用点手写 ±1。
- **坑**：合并时 `block.dispose()` 发生在「该块 controller 正在 notifyListeners」
  的栈里 → Flutter 断言 `_notificationCallStackDepth == 0`。改成
  `scheduleMicrotask(block.dispose)`。
- 顺带：空列表项回车落回正文（否则困在列表里）；TextField 自带 hint 因哨兵永不
  显示，改成叠一层 `Stack(fit: StackFit.passthrough)`。
- 全量 60 测试过。
